# Lore Wave 1 Changelog

## Added

- Native Lore Source Registry with stable lorebook/UID identity, append-only exact source revisions, lineage, structural metadata, and removal tombstones.
- Native Lore Derived Store with revisioned learned publications, historical learned lineage, freshness filtering, conflict exposure, and impact preview.
- First-class Lore Study Engine with bounded structural/contextual reading, entity/alias extraction, atomic claims, relationships, temporal hints, ontology/community foundation, retrieval representations, compact compilation, and validation.
- Lore Study lifecycle runtime with due obligations, deterministic dedupe, supersession, checkpoint/yield/resume, snapshot restore, atomic publication, removal handling, and runtime-compatible authority-negative status.
- Semantic diff based on learned meaning rather than line edits, including value, temporal, authority/unresolved, addition, removal, and preservation signals.
- Public Lore integration surface for downstream Core/Sensory consumption without importing Lore internals.
- Deterministic Ember Tavern golden and negative/edge tests.
- Representative stress and browser-host portability checks.
- Dedicated Lore Wave 1 GitHub Actions workflow.

## Preserved boundaries

- Exact source is independent from derived learning.
- Lore Tree remains human-owned organizational metadata.
- Inference, ontology, retrieval score, embedding metadata, summaries, and communities do not become source authority.
- Ambiguity may remain unresolved.
- No Candidate Bus, Truth Gate, Precision, Gather, Context Seal, Settlement, Jev, Worker Director, UI, final persistence backend, or main/live integration ownership was added.
