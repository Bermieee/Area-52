# Context Compiler Authority Boundary

The Context Compiler is a communication compiler, not a truth owner.

It consumes Truth/Precision output and creates a model-independent ContextPacket. It may choose which settled/current, historical and unresolved knowledge is relevant enough to communicate, merge compatible support, preserve conflicts, expose active unresolved threads and assign deterministic communication priority.

It may not:
- mutate canonical world state;
- change claim authority;
- turn historical evidence into CURRENT;
- turn an unresolved thread into a fact;
- choose a winner among contradictory evidence;
- alter Settlement decisions;
- invent provenance;
- bypass Context Seal.

Compiler semantic priority is an ordering/retention signal only. A high-priority unresolved Sun Blade thread remains UNRESOLVED even when its related evidence moves earlier in a packet.

Compiler diagnostics live in CompilerReceipt. ContextPacket remains the semantic material that Context Seal freezes. Adaptive presentation policies operate only after that seal.
